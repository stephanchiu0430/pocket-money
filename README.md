# 我的零用錢

給孩子用的零用錢記帳 App。手機上記收入和支出，離線也能用；有網路時自動傳到爸爸的 Google 試算表。試算表才是正本，孩子改不了。

- 純前端 PWA：一個 `index.html`，沒有框架、沒有建置步驟
- 後端：Google Apps Script + Google 試算表
- 一個 App 給多個孩子用，第一次設定時選是誰的帳本

## 功能

**孩子看到的**

- 「花錢」、「收到錢」兩個大按鈕，選分類、寫一句說明就記好
- 「對一對」：輸入手上實際有多少錢，跟帳上餘額比對
- 存摺式列表：日期、摘要、支出、存入、餘額
- 記錯了只能「撤銷」，原紀錄劃掉但保留
- 支出超過設定金額時，會問「有先跟爸爸商量過嗎？」

**爸爸看到的（試算表）**

| 分頁 | 用途 |
|---|---|
| 總覽 | 每個孩子的餘額、待確認收入、最近盤點差額、警示筆數 |
| 紀錄 | 孩子傳來的每一筆，含「確認」欄和「警示」欄 |
| 家長入帳 | 爸爸發零用錢、獎勵、扣款 |
| 設定 | 每週零用錢金額、發放日、是否自動入帳 |

## 防篡改設計

放在孩子手機裡的資料，技術上一定改得到，所以這個 App 不靠鎖手機，而是靠下面幾層：

1. **試算表是正本**：每次同步，App 用試算表的資料取代本機快取。已經傳出去的紀錄在手機上改了也沒用，下次連線就被還原。
2. **只能新增**：Apps Script 只有「新增」紀錄的功能，沒有修改或刪除的 API。就算有人拿到網址自己送資料，也刪不掉歷史。
3. **雜湊鏈**：每筆紀錄包含前一筆的 SHA-256 指紋。伺服器收到時重新計算並比對，標出以下警示：
   - 內容被改過（雜湊不符）
   - 前後不連續、前面缺紀錄
   - 帳本重新開始（App 資料被清除或換手機）
   - 時間倒退、時間在未來
4. **收入要確認**：孩子記的收入（紅包等）預設「待確認」，爸爸在試算表改成「已確認」才算進餘額；改成「不算」就排除。
5. **零用錢只能由爸爸入帳**：從「家長入帳」分頁或每週自動入帳。
6. **其他警示**：支出超過餘額、大額未先商量、盤點差額。
7. **家長密碼**：改設定、換網址、重設手機都要密碼（只存雜湊）。這一層只是防君子，真正的防線是上面幾點。

## 安裝

### 1. 試算表與 Apps Script

1. 新建一個 Google 試算表，**不要**分享給孩子。
2. 擴充功能 → Apps Script，貼上 `Code.gs`，存檔。
3. 在函式選單選 `setup`，執行一次並授權。會建立四個分頁，並設定每天早上 7 點檢查是否要發零用錢。
4. 部署 → 新增部署作業 → 類型「網頁應用程式」
   - 執行身分：我
   - 誰可以存取：所有人
5. 複製結尾是 `/exec` 的網址。

之後如果修改 `Code.gs`，請用「管理部署作業 → 編輯 → 版本：新版本」，網址才不會變。

### 2. GitHub Pages

1. 把這個 repo 的檔案放在根目錄：`index.html`、`sw.js`、`manifest.json`、`icon-192.png`、`icon-512.png`。
2. Settings → Pages → 從 `main` branch 根目錄部署。
3. 網址會是 `https://<帳號>.github.io/<repo>/`。

建議用獨立的 repo，不要跟其他 PWA 放在同一個網站的根目錄，避免 Service Worker 的範圍互相重疊。

### 3. 孩子的手機

1. 用 Safari（iPhone）或 Chrome（Android）開啟 GitHub Pages 網址。
2. 分享 → 加入主畫面。
3. 第一次開啟由爸爸設定：選孩子、設 4 到 8 位數字的家長密碼、貼上 `/exec` 網址、設定「多少錢以上要先商量」。

## 平常使用

- **發零用錢**：在「設定」分頁填每週金額和發放日（1＝週一 … 7＝週日），勾「自動入帳」。或在「家長入帳」手動加一列；扣錢就把項目選「扣款」。
- **確認收入**：在「紀錄」分頁把「確認」欄改成「已確認」或「不算」。孩子下次同步就會看到。
- **看警示**：「紀錄」分頁的「警示」欄，或「總覽」的警示筆數。
- **手動更新總覽**：試算表選單「零用錢 → 更新總覽」。

## 更新 App

改了 `index.html` 之後，把 `sw.js` 第一行的版本號加一（例如 `pocket-money-v1` → `pocket-money-v2`）再推上去。孩子手機下次開啟會在背景更新，再開一次就是新版。

```
sw.js           Service Worker，離線快取

```

## 資料格式

每筆紀錄：

| 欄位 | 說明 |
|---|---|
| `id` | `K-<裝置前 8 碼>-<seq>` |
| `seq` | 這台裝置的流水號，從 1 開始 |
| `ts` | ISO 8601 時間（UTC） |
| `child` | 孩子名稱 |
| `device` | 裝置 UUID，第一次設定時產生 |
| `type` | `out` 支出、`in` 收入、`void` 撤銷、`count` 盤點 |
| `amount` | 整數金額 |
| `cat` / `note` | 分類、說明 |
| `ref` | 撤銷時指向原紀錄的 `id` |
| `expected` | 盤點時的帳上餘額 |
| `flags` | `over`、`big:asked`、`big:notasked` |
| `prev` | 前一筆的 `hash`，第一筆是 `GENESIS` |
| `hash` | 上面欄位以 `\|` 串接後的 SHA-256 |

App 的 `canon()` 和 Apps Script 的 `hashOf_()` 必須完全一致，修改任一邊的欄位順序都要同步修改另一邊。

## 同步協定

App 一律用 `POST`（`Content-Type: text/plain`，避免 CORS preflight）：

```json
{ "action": "push", "child": "Luke", "device": "…", "entries": [ … ] }
{ "action": "pull", "child": "Luke", "device": "…" }
```

回應：

```json
{ "ok": true, "entries": [ … ] }
```

`entries` 是這個孩子在試算表上的全部紀錄，包含爸爸的入帳和確認狀態。App 收到後取代本機快取，並把已經出現在回應裡的待送紀錄移除。

## 限制

- 需要 HTTPS（`crypto.subtle`），GitHub Pages 沒問題。
- Apps Script 網址等於寫入權限。外流的話別人可以新增假紀錄，但改不了、刪不掉舊的，而且會被標記裝置。需要時可以重新部署換網址。
- 孩子如果清除 App 資料，還沒同步的紀錄會遺失，試算表會標「帳本重新開始」。
